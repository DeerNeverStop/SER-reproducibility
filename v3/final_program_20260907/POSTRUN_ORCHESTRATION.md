# 原训练进程结束后的单次衔接

`postrun_wait.ps1` 只衔接已经启动的原训练进程，不启动、重启或续跑训练。它按 [命令审计](POSTRUN_COMMAND_AUDIT.md) 顺序调用现有七个步骤：完整门禁和评分、独立数值复算、预定四单位的同 GPU 检查点恢复、绘图、双语事实表、非检查点包导出、异路径解包与复算。全部步骤为新输出，任何非零退出或检查失败都会停止并留下记录；没有自动重试。

脚本需要 PowerShell 7.5 或以上（实测 7.6.5），以及用字节 SHA 固定的本机 JSON 启动合同。JSON 使用 `-DateKind String` 保留精确时间戳文本；合同绑定原 PID、精确 UTC StartTime、进程映像、输出位置、原计划/来源锁和源码字节。脚本在原进程存活时持有其 OS 句柄，等到该进程真实退出；PID 消失或被复用不能当作成功。原退出码必须为 0，正式目录必须恰好有计划中 384 个唯一单位及各自 DONE，才能进入评分。上述目录检查只是初筛，不能替代 `score` 内的全量权重、账本和来源门禁。

外部独占文件锁在 formal 之外，覆盖等待及整个处理链，不占用 `formal/execution.lock`。它协调使用同一锁的调用者；开始等待前和评分前的进程清单检查只是运维快照，不保证阻止绕过外锁的手动调用。这个包装器运行期间，根任务不应另行执行这些后处理命令。

恢复继续使用原研究 Python 和 `cuda:0`。当前合同仅支持已观测到的 CUDA_VISIBLE_DEVICES 未设置状态，只在包装器进程内恢复该状态，不更改用户全局配置或现有训练进程。恢复工具仍自行核对原 torch、torchaudio、CUDA、设备和线程设置；不自动切到 CPU。

控制事件与逐步 stdout/stderr 日志保存在独立 control 目录，每个事件使用独占新建。输出另设同级 scores、audits、figures、paper_facts、bundles、portable_accept 目录。原训练退出前不会读取其预测、选择分数或历史；脚本等待时只持有句柄。评分获准后，原 phase 的完整门禁可以按既有契约写 COMPLETE_GATE、协调合法完成记录，不能把整条后处理链称为只读。

绘图脚本输出仍须根任务逐图目检。便携包不含图件和检查点，因此其机械导出与解包可在图件人工审查前完成；这不构成视觉验收。即使 `90_pipeline_complete.json` 存在，科学解释、论文取舍、中英全文、最终 PDF 和交付源码包仍未完成。
