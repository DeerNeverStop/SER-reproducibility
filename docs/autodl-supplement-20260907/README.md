**推荐一次性确定840次正式拟合，使用一张AutoDL RTX5090／32GB按量运行。**

| 训练组 | 数据与规模 | 轮数 | 新拟合 | 用途 |
|---|---|---:|---:|---|
| HuBERT-base | 三语料，各24draw×5fold | 15 | 360 | 检查当前发现能否扩展到第二骨干程序。 |
| WavLM长窗口 | SUBESCO、RAVDESS，各24×5 | 45 | 240 | 每条自身轨迹比较1–15与1–45选点；前15轮同时提供云端WavLM参照。 |
| WavLM云端参考 | CREMA-D，24×5 | 15 | 120 | 补齐同云骨干参照，并作为角色互换的A方向。 |
| WavLM角色互换 | CREMA-D，同120个面板的B方向 | 15 | 120 | 与本批云端A配对，检查方向平均的政策效应。 |
| 合计 | 720条A轨迹+120条B轨迹 | | **840** | 600条15轮、240条45轮，共19,800个epoch遍历。 |

先前600次建议只含前两组。现在增加的240次都有具体用途：不把“旧本地A／新云端B”当作同环境角色对照，并完整提供本批WavLM参照。这里不是完整的两个骨干×三个语料×长短窗口因子设计；没有HuBERT45轮和CREMA-D长窗口，不能声称已检验这些条件。

**随机化、模型与窗口合同。**

沿用旧冻结元数据面板的说话人、文本、原生类别、代表录音、角色批次与拟合槽规则。三库每次拟合仍为576/224/64条、6/7/8类，训练batch16、3秒裁剪、评估上限10秒，top4+head，encoder/head学习率5e-5/1e-3、weight decay .01。无超参数搜索，不为新模型挑最高外测配置。保留固定角色内padding的既有行为，不能宣称已经消除padding影响。

新计划另用确定性的随机域，五条随机流已按语料/draw/fold写进作业清单，不依赖骨干或A/B方向。分类头在encoder构造之后用独立head种子初始化，同一类别数的两个骨干共享头张量；同骨干A/B完整初始化必须逐张量相等。顺序与裁剪按配对槽共享随机规则。新程序的随机域与历史不同是显式设计，不承诺重现旧5070逐位结果。

P2必须从基座完整训练45轮。旧checkpoint没有完整optimizer、GradScaler和训练RNG状态，不能无损接训。新45轮在第15轮不重置状态；短窗就是这条轨迹的前15轮，训练步本身不得依赖总窗口长短。旧裁剪函数硬限15轮且哈希含旧PROGRAM，新实现须另行扩展和锁定，不直接改旧源码。

每条轨迹、每个窗口应用seen/unseen×CE/UAR四规则，精确并列取最早轮。outer只机械保存预测，绝不参与训练、选点、配置或保留名单。B方向的B query为seen、A query为unseen；同一A/B/outer集合的分批边界不随训练方向改变。所有正式单元完成后再生成科学结果。

**预先固定12项主检验。**

令D为规则选出的模型在共同outer上的seen减unseen UAR差，J为D_CE减D_UAR：

- HuBERT三语料的D_CE与J：6项。
- WavLM两长窗语料的D_CE(45)−D_CE(15)、J(45)−J(15)：4项。
- CREMA-D新云A/B两个方向等权平均的D_CE与J：2项。

全部双侧，先同轨迹差分、P3先方向平均，再在每draw平均五fold，最后以24draw作t检验并统一Holm校正12项。报告全部draw、逐项95%区间及原始/校正p；零方差NA保留家族槽位。原六项结果保留历史身份，不与新检验择优替换。24draw不是新说话人样本量，也不保证12项检验功效。

方向平均显著不等于两个方向都成立，A、B及B−A都要描述报告。两个模型一显著一不显著不证明模型差异；直接骨干对比先描述。小均值不代表等效；窗口、数据和模型的反向结果全部保留。新实验是看过旧结果后的固定设计扩展，不能称全新未接触语料确认。

**云端配置与预算。**

首选Pro规格 `5090-p`，单卡32GB、主机驱动CUDA能力下限12.8。候选公开Miniconda镜像为 `base-image-mbr2n4urrc`，它自带的是旧Python3.8/CUDA11.6，需要另建Python3.11并安装torch/torchaudio2.11.0+cu128。官方Linux cp311 x86_64 wheel已核实存在；这不代表具体实例已通过运行验收。[Pro接口](https://www.autodl.com/docs/instance_pro_api/)、[torch索引](https://download.pytorch.org/whl/cu128/torch/)、[torchaudio索引](https://download.pytorch.org/whl/cu128/torchaudio/)

单卡串行执行，拟合之间按元数据确定的顺序交错骨干/方向，避免整个模型和时间段绑定。所有正式任务固定同主机、镜像与依赖；若平台迫使迁移，暂停并记录，不能悄悄把某个模型或方向换到另一平台。本地GPU不作备选；没有卡时等待或重排AutoDL资源。

默认候选系统盘扩容100GB，实际可写挂载点与容量开机核实。云端采用下述轻量保留合同，不申请同时容纳613GB权重的巨盘。普通AutoDL数据盘计费与Pro系统盘扩容不是同一字段，不能混用费率。

**事前固定的存储合同。**

如果保留全部赢家及两窗口末轮，最多5400份delta，按旧113.46MB代理约612.7GB。推荐新合同：

1. 全840条轨迹的全部epoch、A/B/outer预测，history、角色清单、种子、选择结果、尝试/账本及校验收据永久保存。
2. 每个保存状态都在权重仍存在时完成字节/结构核查和回载预测验证。
3. 七种模型/语料/方向组合，各固定draw0与draw12、fold0，共14个UID，永久保留其全部赢家与末轮权重，并做独立进程恢复。最坏90份delta，约10.2GB。
4. 其余权重只有在验收证据和对应小工件已回传、双端SHA一致后才释放。释放记录追加保存，原DONE与receipt不改写。任何旧实验文件都不清理。

这把“所有预测现在可数值复算”“所有权重当时验收过”“14样本现在仍能权重恢复”明确区分。不能沿用旧全checkpoint gate，不能说840条权重都永久可恢复，14个样本也不代表独立重训练复现。

初始批大小8，限制同时等待回传的批次，磁盘低水位即停止新拟合。输入、环境、模型、暂存和恢复样本留出余量，目标可写空间至少100GB；pilot后按实际体积核定。云端与本地只按清单清理本次可释放的精确路径，不清理原归档或用户其它文件。

1. 在本地完成新模型适配、15/45窗口、B逐轮选点、新gate、评分与独立复算器的实现及CPU合成检查；不在本地训练。

4. 以实际pilot核定价格、时间、显存与存储后，冻结唯一正式源码/环境/面板/统计/保留合同。当前DESIGN.json还不是这一正式锁。
