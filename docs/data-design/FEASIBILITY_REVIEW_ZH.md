# 数据配置研究：可行性复核

日期：2026-09-04。对应两份策划案的 v0.2。结论为**有条件进入实施**，不是新增实验已经证明有效。

## 1. 判断与优先级

| 工作 | 难度 | 论文价值判断 | 建议 |
|---|---|---|---|
| 固定录音预算、比较人数和句子配置 | 中 | 能把已有协议分析推进到实际数据选择，但普通单调趋势的新意有限 | 首轮主实验 |
| 开发集配置建议器及独立评价 | 中 | 可交付程序；搜索本身不是新算法，须证明相对简单策略的效用和成本 | 首轮工程产物 |
| 相同配置下比较已见/未见句子 | 中 | 有助说明建议的适用条件；必须排除覆盖量变化的混杂 | 共同配置可行后纳入 |
| 冻结规则预测新预算或独立语料 | 中高 | 比在每个语料重新搜索更能支撑可迁移的结论 | 增强贡献的优先方向 |
| AI 合成情绪语音与声线扩充 | 高 | 已有近邻工作；生成质量、真实声线多样性和真实测试迁移均需另证 | 不作为首轮依赖 |
| 多语言、噪声、方言、真实客服部署同时展开 | 高 | 容易重新变成碎片化结果，且需要对应的真实数据 | 暂缓 |

最合适加入当前论文的是：**有限训练预算下的配置比较 + 有成本记录的开发选择 + 独立测试**。第一版建议器帮助从已有语料中选录音；推广到现实采集人数或客服部署，需要新增证据。不能保证该扩展一定达到目标会议的创新要求。

## 2. 已完成的元数据构造验证

验证程序为 [feasibility_check.py](feasibility_check.py)，完整记录为 [feasibility_snapshot.json](feasibility_snapshot.json)。程序只读仓库中的真实 CSV 清单，独立执行已记录的字节重复与坏文件清理规则，不读取音频、特征、预测或训练成绩。

| 语料 | 原始记录 | 清理后记录 | 说话人 | 句子 | 情绪类别 | 不同人×句子×类别单元 |
|---|---:|---:|---:|---:|---:|---:|
| CREMA-D | 7,442 | 7,435 | 91 | 12 | 6 | 6,525 |
| SUBESCO | 7,000 | 6,998 | 20 | 10 | 7 | 1,400 |

CREMA-D 删除 6 条冲突标签的字节重复记录和 1 条已有坏文件记录；SUBESCO 删除 2 条同标签字节重复记录。CREMA-D 每个单元取按路径排序的固定一条代表录音，不把强度编码当作真实重复。

构造范围：5 个固定外层说话人折 × 3 次确定性抽样 × 候选/最终两个阶段。

- CREMA-D：预算 288/576 条，人数 12/24/48，固定全局 8 句和每单元 1 条。两种句子条件下保持相同人数、人均句子数和类别配额，并使用共同可供给的训练说话人；共 **360** 组面板。
- SUBESCO：未见句子条件，预算 224 条时采用 `(人数, 每人句子, 重复) = (8,4,1)、(4,4,2)、(8,2,2)`；预算 448 条时重复数分别增至 2/4/4，共 **180** 组。早停集合在同阶段的不同配置间固定。

**总计 540 组面板均成功构造。** 检查了精确录音预算、完整均衡的类别配额、人数与句子覆盖、真实重复供给、唯一文件/字节身份、训练与留出说话人隔离、未见句子隔离，以及已见句子的实际训练覆盖。快照包含清单 SHA-256 和各面板、测试、早停、选择集的身份摘要。

这证明上述清单、划分规则和抽样下存在合法训练面板。**540 是元数据面板数，不是训练次数、识别实验结果或独立统计样本量。**

复现命令（仓库根目录，Python 3.10+，仅标准库）：

```shell
python docs/data-design/feasibility_check.py --check docs/data-design/feasibility_snapshot.json
```

重新生成快照：

```shell
python docs/data-design/feasibility_check.py --out docs/data-design/feasibility_snapshot.json
```

## 3. 复核后已写入方案的修正

| 风险 | 修正 |
|---|---|
| 先看先导开发成绩再改全局设计，同一人后来成为另一外层折的测试对象 | 首轮先导仅看工程故障、容量和耗时；正式全局范围在成绩可见前固定。科学先导另用独立人群或标为探索性 |
| 已见/未见条件的可用句子数不同，混淆内容重叠与覆盖数量 | Q2 使用共同配置 ID，固定人数、全局/人均覆盖、重复和类别配额，最终重训练也不得扩大量 |
| 旧早停分数冒充配置选择分数 | 从独立选择集预测重算固定类别、说话人等权 UAR；旧 `val_uar_best` 不用于推荐 |
| 类别缺失静默改变 UAR 定义 | 计划阶段核验固定类别覆盖；按预定规则处理，不能临时缩减类别集合 |
| 旧 Ridge 的零计时被当作零计算成本 | 新适配器独立记录调用墙钟、引擎训练时长和一次性准备成本 |
| 推荐后没有明确最终运行清单 | 初始计划冻结选择/重采样规则；根据开发结果哈希生成选择回执，再编译、核验并锁定最终计划 |
| 把多强度录音当作真实重复 | CREMA-D 单元内固定代表；重复实验使用 SUBESCO 的真实 takes |
| 随机基线被额外的人均完整类别条件削弱 | 普通随机仅满足共同的全局类别预算；受约束随机单独命名 |
| 建议器与穷举或全空间随机搜索等价，却写成不同算法 | 等价方法合并；只有候选选择算法不同且搜索未穷尽时才另设等成本随机搜索 |
| 缺清单时旧入口可能生成合成夹具、多个缓存时自动选一个 | 新正式入口须拒绝缺失、歧义及身份不匹配；旧冻结研究目录保持不变 |

## 4. 算力与工期是否可接受

本次会话先前硬件盘点为 RTX 5070 12GB、Ryzen 7 9700X、32GB 内存。相近历史小样本任务的从头训练约 15–40 秒/次、缓存探针约 1–3 秒/次；这些是迁移估计，不是本方案的新实测。

详细方案示例包含 360 次候选拟合和最多 600 次最终拟合，共 960 次，尚未合并同身份任务，也不含 SUBESCO 附属块。若一半为探针、一半为从头训练，按上述历史单次范围计算累计约 2.1–5.7 小时；若全部从头训练约 4.0–10.7 小时。环境准备、特征提取、输入输出、额外重复和其他任务争用另计；不能将这些数当作交付时间或云租用时间。

因此建议先在本机实现并测量少量代表单元，无需现在就租云 GPU。只有代码就绪后，本机排队明显影响期限、实测吞吐不足或模型显存超出容量，再评估独立云运行。首轮工程约 2–4 个有效工作日，形成完整对照和报告约 1–2 周有效工作；均为规划估计。

此次复核没有运行新训练，没有更改正在执行的旧实验，也没有租用服务器。旧训练排期和云价格快照不是此次提交的实时状态。

## 5. 尚未证明什么，何时决定论文如何使用

当前验证**不覆盖**完整正式规划器、所有随机/结构化基线、音频质量、缓存接入正确性、神经模型训练、新数据上的 UAR 收益、统计功效或创新性。元数据演示中的确定性面板也不是已经预注册的最终试验设计。

进入实施需补齐正式候选与最终计划、严格引擎适配、基线配额、失败恢复和关键故障测试。正式结果前固定主对比、最低实际关注差异、统计单位和迁移目标；无需预设哪条策略获胜。

- 若相对简单均衡/人数优先策略有稳定收益，且选择成本合理，可作为当前论文的一节配置方法与验证。
- 若冻结规则还能预测独立预算或语料，可考虑提升为更强的核心贡献。
- 若复杂选择器无优势，则给出简单策略、成本和适用边界；不能把最高开发分数包装为改进。

近邻文献与现有工程依据见 [详细策划案第 14 节](PLAN_FOR_CLAUDE_ZH.md#14-阅读材料与来源)。这一评估是实施决策依据，不是接收概率预测。
